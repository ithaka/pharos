## Usage

Use the sidenav to host more navigational menu options than is possible for a simpler top
navigation layout, making it much more easily scalable. The sidenav is also easier for a user
to scan the items, as it acts like a list, helping give users a more focused experience.

## Best practices

<BestPractices>
  <Fragment slot="do">
    - The primary links representing main sections of the site should be listed first
    - If needed, group navigation items into sections based on related categories.
    - Use short and concise verbiage menu option and section heading text
    - Keep the links consistent throughout the site
    - Sidenav Components:
      - Use the section sub component when trying to create groupings of menus and link that are
        visible at all times
      - Use the side menu sub component inside the sidenav component when trying to create a
        dropdown type of menu in the navigation
      - Use the link sub component when trying to create a static link
  </Fragment>
  <Fragment slot="dont">
    - Don't use icons to represent the navigation items, alone or with text, reserve icons for
      use within the UI
    - Don't move the placement of the sidenav to the right side of the content, it should always
      be fixed to the left
    - Do not nest or group menu options more than one level of hierarchy, we want to keep the
      navigation simple and understandable. If you find you need to nest, reconsider the
      information architecture.
    - Don't use the sidenav component if there are less than 3 menu item options, instead of a
      top navigation layout
    - Don't use any of the 3 sub components outside of the sidenav component
    - Don't use the sidenav to display important system or site information
  </Fragment>
</BestPractices>

## Content guidelines

A navigation menu acts as a table of contents for your site. The content of links should
reflect this hierarchy. The primary links representing main sections of the site should first
be listed. If applicable, add submenus to links with additional related sections with a list of
links pertaining to that group. Also, use sentence case for primary and secondary navigation
items.

## States

### Link

#### External

The sidenav link sub-component has an <code>external</code> state which places the external icon
at the end of the row and causes the link to be open in a new page/tab.

### Section

#### Show divider

The sidenav section sub-component has a <code>showDivider</code> state, which places a divider
below the section.

## Variants

### Mobile

The sidenav component has built-in responsive design which hides the menu for any width lower
than 1056 pixels. In order to show the menu again, use the button sub-component for a manual
toggling experience. The navigation appears over the top of the content with an overlay over
the underlying content.

### Importance

Helps users get an overview of the hierarchical content available on the site and how to
navigate them.

### Visual expectations

A vertical menu that can contain links, sections and expandable menus

### Code expectations

- The parent component is a nav element
- The menu sub-component is an unordered list

### Expected actions

#### Screen reader

Reads items in order from top to bottom

#### Keyboard

- <kbd>Tab</kbd>: moves focus onto the dropdown. When dropdown is expanded, focus will go
  to next menu item
- <kbd>Shift</kbd> + <kbd>Tab</kbd>: When dropdown is expanded, moves focus to the previous
  menu item
- <kbd>Enter</kbd>: opens dropdown, interacts with selection when focus is on a menu item
