## Usage

### About the Grid

The Pharos layout component hinges on the structure of a responsive grid. A grid is like the
invisible glue that holds a design and experience together.

<site-pharos-heading level="4" preset="1--bold">Organizes</site-pharos-heading>

The grid creates organized, consistent product layouts by providing a standard for
positioning elements.

<site-pharos-heading level="4" preset="1--bold">Improves efficiency</site-pharos-heading>

The grid speeds up designer-to-developer workflow by improving consistency of design
implementations.

<site-pharos-heading level="4" preset="1--bold">Creates shared standardization</site-pharos-heading>

The grid lays out and aligns content by applying standard spacing between elements on a page
or within a component.

### Elements of the grid

<Image src={gridElements}
  alt="The elements consist of a gutter, column and margin"
  class="pharos-storybook__image" />

<site-pharos-heading level="4" preset="1--bold">Column</site-pharos-heading>

There's a maximum of 12 columns in the Pharos grid, as seen in the layout component. Columns
segment the content visually and help bring organization to the page and create visual
hierarchy. The column structure in the layout component optimizes for the screen size, and
maintains design integrity across breakpoints. We reduce the number of columns at smaller
breakpoints to maintain consistent gutter spacing at each breakpoint.

<site-pharos-heading level="4" preset="1--bold">Margin</site-pharos-heading>

Creates an invisible frame around content and allows for visual breathing room. The margins
change depending on the variant needs for the layout component.

<site-pharos-heading level="4" preset="1--bold">Gutter</site-pharos-heading>

Gutters are the spaces between the columns. In Pharos, gutters remain consistent across all
breakpoints. They provide enough spacing between content and columns without being too
efficient, giving great emphasis to the content. We believe simpler, well-spaced, and
well-designed layouts make the content easier to understand.

<site-pharos-heading level="4" preset="1--bold">Breakpoints</site-pharos-heading>

Pharos has a set of standard breakpoints to maintain layout integrity across screen sizes.
For best results, create and test designs and code at each of these standard breakpoints to
create the best layout for the screen's real estate.

### How it works

The grid uses CSS grid to structure content in columns and rows to layout and align the
content. An outer grid is used to establish the margins defined for each preset on the
various breakpoints. A second inner grid is used to establish the columns and gutters.

## Grid principles

### The grid supports the needs of typography

<site-pharos-heading level="4" preset="1--bold">Prioritize ideal line-length</site-pharos-heading>

When displaying copy in a layout, it should be read easily and comfortably. Overly long and
overly short widths of text tire the user. The right width is essential to create an even
and pleasant reading experience. On the web, 45 to 85 characters is optimal per line, with
65 characters being the ideal amount.

<site-pharos-heading level="4" preset="1--bold">Well-proportioned margins</site-pharos-heading>

Margins can determine the maximum width of a block of text. If margins are too small, the
reader can feel that the page is "overfull". If margins are too large, it's difficult to
avoid a sense of extravagance.

<site-pharos-heading level="4" preset="1--bold">Spacing paired with font choices can create a useful rhythm</site-pharos-heading>

We use our two typeface families to enable a visual rhythm on our pages, most specifically
with our search results. Our titles are set in our serif font and the metadata is set in our
san-serif font. We pair this approach with adequate spacing between results to create better
scannability between items and predictability.

### Employ whitespace intentionally

A grid organizes space as much as it does the content that's in it. Intentional spacing
helps establish focus, order, and emphasis, guiding the user through a page or an
experience. Without enough whitespace, the composition can appear chaotic and unorganized.

### Establish purpose with layout

<site-pharos-heading level="4" preset="1--bold">Elevate the content</site-pharos-heading>

We want our users to be able to focus on what they're searching for and reading/evaluating.
So we aim to have our content amplify that experience rather than distract from it. Images
should have sufficient spacing around them to give them greater focus on the item itself,
apart from the surrounding images.

<site-pharos-heading level="4" preset="1--bold">Maintain layout integrity across screen sizes</site-pharos-heading>

Layouts should be intentionally designed and optimized for each of our standard breakpoints.
While designing, the integrity and structure of the page's layout should be maintained as
best as possible across the screen sizes.

<site-pharos-heading level="4" preset="1--bold">Layout selection</site-pharos-heading>

Select the best layout for the needs of the page, JSTOR has a few layouts (as described
below) for our experiences.

## Best practices

## Variants

### One column

The one column layout is used on a majority of JSTOR's product pages. The page's content has
a max-width at each breakpoint, but the layout is still fluid. The page's content is
horizontally centered in the browser.

### Two column

The two column layout has a fluid width, the page's content using this layout uses 100% of
the screen's width. It's used to separate two large sections of content into separate
layouts on the page. It's to be used sparingly, mostly with content viewing experiences.

### One column with sidenav

Use this layout when a page or experience needs a sidenav and a focused layout. It has a
fluid width, with consistent margins throughout the breakpoints.

### One column with sidenav and comfy spacing

This layout has extra spacing in the margins to have a more spacious experience.

### Visual expectations

- Focus goes in the logical reading order, left to right, top to bottom
- All content and functionality (or its equivalent) can be accessed regardless of screen
  size or orientation

### Code expectations

- Grid layout sections should use semantic html
  - Ex: sections such as "header", "footer", "nav", "aside", "main" and "article"

### Screen reader

- All content is read in the logical reading order
