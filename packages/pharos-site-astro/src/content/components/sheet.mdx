## Usage

### Overview

Sheets are overlay panels that emerge from the bottom of the viewport. They are primarily designed
for mobile and touch-based interactions, allowing users to view supplemental content or take
contextual actions without losing their place in the page.

Sheets support drag-to-expand behavior, allowing users to reveal more content by dragging the
handle upward. They can also be configured to dock in place rather than fully close.

### When to Use

- To present supplemental content or options related to the current page without navigating away
- When a lightweight overlay is needed on mobile that does not obscure the full screen
- For filter panels, quick-actions menus, or contextual details
- When a docked persistent panel is needed at the bottom of the viewport

## Best practices

<BestPractices>
  <Fragment slot="do">

    - Use for supplemental, contextual content that does not require a full page transition
    - Provide a clear way to dismiss the sheet (drag handle, close button, or overlay tap)
    - Keep sheet content focused and avoid overwhelming the user with too much information
    - Use the docked variant when the sheet should remain visible as a persistent bottom panel

  </Fragment>
  <Fragment slot="dont">

    - Don't use sheets for primary navigation or content that requires its own page
    - Don't nest sheets inside other overlay components such as modals or dialogs
    - Don't place critical, irreversible actions inside a sheet without confirmation

  </Fragment>
</BestPractices>

## Content guidelines

### Sheet header

The sheet header should briefly describe the content or purpose of the sheet. It should be written
in sentence case and be concise. Punctuation is generally not needed in headers.

### Sheet body

The body can contain any content, including text, form elements, lists, or interactive components.
Keep the content relevant to the context that triggered the sheet.

## Variants

### Base

The default sheet slides up from the bottom. It can be dismissed by tapping the overlay, dragging
it down, or pressing Escape. The handle at the top allows the user to drag and expand the sheet.

### With close button

Use the `has-close` attribute to render an explicit close button in the sheet header. Useful when
it is important to give users a clear, visible affordance for dismissal.

### Expanded

The sheet opens in its fully expanded state when the `expanded` attribute is set. Use this when
the content requires more vertical space by default.

### Docked

A docked sheet persists at the bottom of the screen rather than closing when the overlay is
tapped. Tapping the trigger again expands the sheet to its full height. Use the `docked` attribute
to enable this behavior.

### Omit overlay

Use `omit-overlay` to render the sheet without a background overlay. This is useful when the sheet
should sit alongside page content without obscuring it.

## Accessibility

### Relevant WCAG guidelines

- [1.3.1 Info and Relationships A](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships.html)
- [2.1.1 Keyboard A](https://www.w3.org/WAI/WCAG21/Understanding/keyboard.html)
- [2.4.3 Focus Order A](https://www.w3.org/WAI/WCAG21/Understanding/focus-order.html)

### Importance

Sheets should not open automatically, as this can disrupt a user's workflow. Users should always
initiate opening a sheet via an explicit action. When a sheet opens, focus should be moved into
the sheet and trapped there until it is dismissed.

### Code expectations

- The sheet container uses `role="dialog"` and `aria-modal="true"`
- The sheet uses `aria-label` sourced from the `header` attribute to provide an accessible name
- Focus is trapped within the sheet while it is open; no elements behind the overlay should be
  reachable via keyboard
- When the sheet closes, focus is returned to the element that triggered it
- The close button (when present) has an `aria-label` of "Close sheet"

### Expected actions

<site-pharos-heading level="4" preset="1--bold">Screen reader</site-pharos-heading>

- Announces the focused element within the sheet and reads "dialog" to indicate the overlay
  context
- The close button reads as "Close sheet, button" when focused

<site-pharos-heading level="4" preset="1--bold">Keyboard</site-pharos-heading>

- <kbd>Tab</kbd>: moves focus forward within the sheet
- <kbd>Shift</kbd> + <kbd>Tab</kbd>: moves focus to the previous element in the tab order
- <kbd>Esc</kbd>: closes the sheet
